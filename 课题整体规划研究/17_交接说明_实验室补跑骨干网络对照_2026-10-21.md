## 0. 为什么跑

本人 10-21 问：「R² 低是不是 ResNet-18 不好？换新模型效果会不会更好？」主文的表示 / 视角消融都用 ResNet-18 基线（高度图 3 种子 R² 0.336），审稿人也可能问「为什么用 ResNet-18」。本实验在**完全相同的协议**下换 4 种较新、较大的骨干网络，看 R² 能否明显提高（DECISIONS 2026-10-21）。

- 新脚本：`背膘算法/twoview/v6s_backbones.py`。它把 `v4b_hmap_models.py` 里的网络换掉后直接调用 `v4b.main()`，所以折、内层验证集选 epoch、帧质控、输入、增广、损失、学习率、15 epoch、batch 64、种子 42–44 都与 ResNet-18 基线完全一致，只是网络不同。
- 结构（参数量为换成单输出后的实际值，ResNet-18 为 1 120 万）：ResNet-50（2 350 万）、EfficientNet-B0（400 万）、ConvNeXt-Tiny（2 780 万）、Swin-T（2 750 万，Transformer）。都用 torchvision 的 ImageNet 预训练权重；第一层卷积按通道取平均改为单通道，输出层初始化为训练集均值（与 ResNet-18 基线相同）。**不为各结构单独调参**（固定配方，写稿时注明）。
- 不含 Mamba：视觉 Mamba（Vim、VMamba、MambaVision）依赖 `mamba_ssm` 的 CUDA 扩展，官方只支持 Linux，Windows 上需要 WSL2 另建环境。本人若要加，先停下来问。

## 3. 运行

在 `<仓库>\背膘算法\twoview\` 下：

```
set BACKFAT_RUNS=D:\gengls\backfat-paper\背膘算法\twoview\runs_v6o
set BACKFAT_INDEX=D:\gengls\backfat-paper\背膘算法\twoview\runs_v6o\index_v2_v6o.csv
python v6s_backbones.py --arch resnet50 efficientnet_b0 convnext_tiny swin_t --weights-dir D:\backfat_weights
python v6s_backbones.py --compare
```

想更快可以开两个命令行窗口并行（两个窗口都先执行上面两条 `set`）：窗口 1 `--arch swin_t resnet50`，窗口 2 `--arch convnext_tiny efficientnet_b0`；两边都结束后再运行一次 `--compare`。32 GB 显存够两路并行，不要再开第三路。

- 用时：ResNet-18 基线在这台电脑上 3 种子约 15 min（10-20 summary 的 v4b）。笔记本（RTX 4060）冒烟测试中每种结构 1 个 epoch × 5 折的用时：ResNet-50 2.3 min、EfficientNet-B0 1.3 min、ConvNeXt-T 2.2 min、Swin-T 6.3 min；按 15 epoch × 3 种子推算，5090 上**串行合计约 2–3 h**，Swin-T 最慢。也可以开两个窗口各跑两种结构（每个进程显存约 4–8 GB）。
- 断点续跑：按种子存断点（`runs_v6o\v4_hmap\bb_<arch>\_seed_ckpt\`），中断后用同一命令再跑即可。
- 输出：`runs_v6o\v4_hmap\bb_<arch>\{log.txt, result.json, test_preds.csv, frame_preds.csv}`；对照结果在 `runs_v6o\v6s_backbones\{log.txt, result.json}`，内容是各结构相对 ResNet-18 的 ΔR²、ΔMAE（按猪 bootstrap 95% CI）和 Wilcoxon p，以及每个种子的 R²。

笔记本冒烟测试（10-21，临时 runs 副本、每种结构 1 epoch、1 个种子、不加载预训练权重）：4 种结构均跑通 5 折，`--compare` 正常输出；正式 `runs_v6o` 未被写入。
