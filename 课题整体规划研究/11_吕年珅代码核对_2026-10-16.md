## 0. 结论速览

1. **选模与报告**：他用验证折选 checkpoint（耳标级 MAE 最小）并做早停，报告的也是这个验证折的结果 → 与我们的 testsel 口径相同。我们按此口径 R² 0.405。
2. **R² 算法**：先在每头猪内对全部点云预测取**中位数**，再用 sklearn `r2_score` 计算；稿件报告 5 折的平均值。这种算法不会让数字变好：我们按中位数聚合反而略低（0.342 vs 0.352），按 5 折平均也略低（0.400 vs 0.405）。
3. **标签**：他的标签与我们**同源**（我们 663 条中有 660 条的背膘值出现在他的表中）。但他的匹配**不看日期**：同一耳标测了两次时，所有点云都用表中最后一个值。这只增加噪声，不会让结果虚高。
4. **样本范围**：稿件写明只含 9–25 mm 的猪（SD 3.39 mm）；原始表为 8–33 mm（SD 4.33）。我们把测试猪限制在 ≤ 25 mm 并用 testsel 口径：R² 0.364、MAE 2.12。
5. **差距的位置**：口径、R² 算法和样本范围加起来只能解释一小部分，MAE 仍差约 0.4 mm。他 **4 月的独立测试集**结果是 R² 0.31–0.43、MAE 2.22–2.42，**与我们 0.375 / 2.34 相当**。数字跳到 0.6 以上发生在 6–7 月换成新数据集版本之后（`new1` / `pcd_body_dataset_618` / `630`）。这些版本是怎么生成的，拷来的资料里没有。
6. **可疑的筛选脚本**（是否用于最终数据集〔待问〕）：
   - `MAEfliter.py`：按模型预测误差 > 2.5 mm 剔除耳标，train / val / test 都剔；
   - `backfatexclude.py`：剔除背膘 29 / 30 / 31 mm；
   - `bfbcxgxfx1.py`：按「背膘—体况」回归残差列出异常耳标，只输出名单。
7. **五折脚本、最终数据集、逐头预测都不在拷贝里** → 第 6 项（在共有的猪上同口径重算）现在做不了。

**对稿件的含义**：两稿的数字差距主要来自数据版本和样本筛选，不来自模型或 R² 算法。正文不直接比较两稿数字，Discussion 只做技术路线上的定位。如导师要同口径对照，可写「按吕年珅稿相同的选模协议，本文 R² 0.405」。

## 2. 六项核对（10 交接 §4）

### 2.1 选模方式 → 验证折既用于选模，又用于报告（= 我们的 testsel）

- `tools/runner_finetune.py:711-725`：每个 epoch 在 `config.dataset.val` 上验证；耳标级 MAE 更低就存 `ckpt-best`；连续 50 个 epoch 没有改进就早停。
- 训练日志里每行 `[Validation]` 就是这个集合；稿件的五折设计是「每次 1 折作验证集，其余 4 折训练」，**没有独立测试集**（稿件 §1.3 末段）。
- 同一配置、同一 `seed 0` 反复重跑了多次（如 `20260701-154046_630_…` 下有 17 次子运行，最佳验证 R² 0.590–0.644）。稿件没有说明报告的是哪一次。

### 2.2 R² 怎么算 → 每头猪取中位数，sklearn r2_score，5 折平均

- `runner_finetune.py:760-782`：按 `ear_id` 分组，对该猪全部点云预测取 `np.median`，标签取该组任意一个点云的标签，再计算 MAE、RMSE 和 `r2_score`。
- 稿件表 2 报告 5 折各自的 MAE / R²，并取平均。
- 我们按这两种算法重算（`v6_anatomy/prof/test_preds.csv`、`v6_anatomy_nested/frame_preds.csv`）：

| 本文主模型 | R² | MAE |
|---|---|---|
| inner，合并 | 0.375 | 2.34 |
| inner，5 折平均 | 0.369 | 2.34 |
| testsel，合并 | 0.405 | 2.27 |
| testsel，5 折平均 | 0.400 | 2.27 |
| 帧聚合用均值（嵌套单种子，按记录） | 0.352 | 2.37 |
| 帧聚合用中位数（同上） | 0.342 | 2.39 |
| 按他的方式把同一耳标的两季合并成一头猪（均值） | 0.327 | 2.27 |

→ 中位数聚合、5 折平均都**不会**提高 R²。

### 2.3 标签匹配 → 与我们同源；不按日期，同耳标多次测定只取最后一个值

- `labesjsonmake.py`：只读 Excel 的「耳标、背膘」两列，构建 `ear2label` 字典。耳标标准化会去掉栏位前缀（`80A287` → `A287`），这一步是对的。后出现的行会覆盖先出现的行，**没有日期列**。
- `YOLO/backfat.xlsx` 的情况：
  - 1 557 行，标准化后 1 308 个耳标；
  - 228 个耳标出现 2 次，其中 192 个两次的值不同（如 A282：10 vs 17 mm）；
  - 有 1 个明显录入错误（70 mm）。
- 与我们对比：
  - 我们 663 条记录中，662 条的耳标在他的表里，660 条的背膘值等于他表中该耳标的某一次测定 → **同一套 B 超记录**；
  - 211 条记录属于测了两次的猪，其中 100 条按他「取最后一个值」的规则会配到另一季的值，平均差 1.5 mm。
- 影响：如果他的点云覆盖了两次测定日期，这部分标签就有错配，增加噪声（拉低他的 R²），**不会造成虚高**。

### 2.4 每头猪的帧 / 点云数 → 约 132 个点云，取中位数

- 稿件：按 15 f/s 抽帧，每头猪约 3 min 视频，体素下采样后点数不够的舍弃，最终 126 499 个点云 / 958 头，**平均每头约 132 个**。每个点云用 FPS 采到 2 048 点。
- 我们：每条记录 10–20 帧（平均 18.6）。重复性分析中 1 / 5 / 20 帧的 R² 为 0.21 / 0.33 / 0.35，已接近饱和 → 帧数差异预计贡献不大。
- 帧级质量筛选：`zitaishaixuan3.py` 按 PCA 主轴弯曲角 > 10°、高度异常 > 0.1 m 剔除帧（体态筛选）。是否用于最终数据集〔待问〕。

### 2.5 958 头的构成 → 只含 9–25 mm；有多个筛选脚本

- 稿件 §2.4：全数据集背膘 17.34 ± 3.39 mm，分为 9–13 / 14–20 / 21–25 mm 三段，共 140 + 642 + 176 = 958 头 → **≥ 26 mm 的猪都不在数据集中**（原始表中有 72 条 ≥ 26 mm）。
- 筛选脚本：
  - `backfatexclude.py`：从 `pcd_body_onlyhead_dataset_622_npy` 中剔除 29 / 30 / 31 mm，生成 `…_630_npy`；
  - `MAEfliter.py`：读 `result/{train,val,test}_id.csv` 中的模型误差，**只保留误差 ≤ 2.5 mm 的耳标**，train / val / test 都这样处理（目录名带 `flitered`）。这是按结果筛样本：如果用于最终评估，会直接虚高；
  - `bfbcxgxfx1.py`：「背膘—体况」回归残差 > 2 / 3 SD 的耳标列成名单（只输出，不复制文件）。
- 我们的 A 场：17.94 ± 3.80 mm（9–31）。只看 ≤ 25 mm 的测试猪：SD 3.37（与他的 3.39 一致）；inner R² 0.330、MAE 2.19；testsel R² 0.364、MAE 2.12。

### 2.6 共有猪上的同口径重算 → 现在做不了

- 拷贝里只有日志中的汇总指标，没有逐头预测和折号。需要向他要五折各折的 `耳标, 折号, 真值, 预测` 表。拿到后可以在两边共有的猪上用同一套指标重算（共有的猪约 560 头）。

读法：
- 4 月 `new2` 的验证折与独立测试相差约 1 mm MAE：验证集很小，又兼作选模，数字明显偏乐观。这是「验证折兼作报告」偏乐观的直接证据。
- 4 月的独立测试水平（0.31–0.43 / 2.2–2.4）与本文相当。
- 6 月以后，同类模型在新版本数据上的验证 MAE 稳定降到约 1.6，7 月独立测试也到了 1.58。所以**差距主要出现在数据集版本切换**：样本、点云、筛选可能都变了。拷来的资料无法判断具体是哪一步，需要吕年珅说明 618 / 630 / new1 的生成过程。

## 4. 能用、能借鉴、能参考的

### 4.1 写作可直接用或引用
1. **误差按背膘分段**：他的图 9 按低 / 中 / 高背膘段画绝对误差箱线图，两端误差大（1.91 / 1.53 / 2.43 mm）。我们有校准斜率 0.37、新美系低估等结果，可以画同类的分段误差图（放 Fig 4 或补充材料），两稿结论互相印证：都有回归向均值。
2. **体况评分与背膘的相关**：`相关系数分析结果.xlsx`，n = 1 040，Pearson r 0.468。我们人工卡尺与背膘 r 0.48，同批猪、结论一致，可作为 Discussion 的旁证（引用他的稿件）。
3. **计算量与参数量**：他的表 3 报告 GFLOPs 和参数量（PointMamba-PCGL 1.261 GFLOPs / 1.306 M）。我们的 Table 4（Jetson）也应补上主模型的 GFLOPs 和参数量。可参考他的 `complexity/`、`profile_model.py`，但我们自己用 thop / fvcore 计算。
4. **引言定位**：同批猪、两台相机（Femto Bolt / Azure Kinect DK）、两条技术路线。他：深度图 YOLO11n-LS + 直方图分割 → 点云 PointMamba-PCGL；本文：RGB 分割 → 物理尺度高度图 → 解剖引导 2D 网络，面向边缘部署。两稿互相引用。
5. **评估协议讨论的素材**：「验证集兼作选模和报告会偏乐观」可用他 4 月验证 vs 测试的差距说明。不过这是同门未发表的数据，**正文不点名使用**，只在与导师讨论口径时作内部依据。

### 4.2 方法上可借鉴（都不改变主结论；做不做〔待本人定〕）
1. **帧级体态筛选**（`zitaishaixuan3.py`：主轴弯曲角、高度异常）。我们目前没有显式的帧质量门控，MIL 注意力是负结果。可以在 Discussion 中作为改进方向；也可以用一个廉价的 CPU 实验验证：在已有的逐帧预测上按高度图形状剔帧后重新聚合。
2. **Z 向直方图分割限位栏**：与我们 v5b 的栏杆列判定思路接近。Methods 中可引用他的稿件说明同类做法。
3. **加权 MSE**（w = exp(0.5|z|)，上限 4，针对两端）：我们 E07 的密度倒数加权已经试过（R² 0.368，校准斜率 0.366 → 0.397，不优于基线）。思路相同，**不建议再跑**。
4. **中位数聚合**：已验证不优于均值（§2.2）。

### 4.3 不能用的
- 他的 958 头点云：相机是 Femto Bolt，不是 DK，不能直接并入我们的高度图训练。
- 他的标签表：与我们同源，不提供新信息；但发现了 1 处 70 mm 录入错误和两次测定的耳标，可提醒他。
- `lung_*`、`WQ`、两个 conda 环境：与本课题无关。
